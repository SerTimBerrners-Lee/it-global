# it-global

Сайт IT Global: внедрение корпоративных сервисов на инфраструктуре клиента.

Сайт на HTML, CSS и JavaScript. Небольшой сервер отдаёт страницы и отправляет заявки на почту. Сборка интерфейса не требуется.

## Возможности

- Единый каталог из 17 решений в верхнем блоке с логотипами, фильтрами и поиском по продукту или его замене. Почта на Mailu, локальный ИИ на подходящих открытых компонентах и моделях с проверкой их лицензий.
- Добавление сервисов в общий набор с сохранением выбора в браузере.
- Два формата внедрения: один сервис за 9 900 ₽ или весь набор за 49 900 ₽, с годом поддержки каждого сервиса.
- Калькулятор расходов и окупаемости: свой сервер или VDS с резервными копиями за 3 000 ₽/мес. Если переход дороже, показывает дополнительные расходы вместо отрицательной экономии.
- Выбор сервисов и отправка заявки на email через сервер.
- Адаптивная версия для компьютеров и телефонов.
- Двенадцать страниц для поиска: почта, файлы, документы, CRM, пароли, проекты, видеовстречи, переход с облачных подписок и четыре задачи локального ИИ. Страницы и все 17 продуктов каталога приходят в готовом HTML без выполнения JavaScript.

## Локальный запуск

Нужен Node.js 22.21 или новее. Из корня репозитория:

```sh
npm ci
cp .env.example .env
npm start
```

Перед локальной проверкой установите `NODE_ENV=development` в `.env`. Откройте http://127.0.0.1:8765. На Windows скопировать файл можно командой `Copy-Item .env.example .env`. Не перезаписывайте существующий `.env` с заполненными настройками.

Без почтового пароля страницы работают, а форма честно сообщает о временной недоступности отправки. Обычный статический сервер подходит только для просмотра страниц, отправка заявок на нём не работает.

## Заявки

Форма содержит выбор сервисов, имя, телефон и описание задачи. Выбор сервисов синхронизирован с каталогом. После нажатия «Отправить заявку» сайт передаёт данные на `POST /api/requests`. Сервер проверяет поля, самостоятельно подставляет названия продуктов и пересчитывает суммы. В письмо входят контакты, выбранные продукты, год поддержки и предварительный расчёт. Формат внедрения определяется по количеству сервисов; сценарий калькулятора указан отдельно.

Отправитель и получатель: `david.perov60@gmail.com`. Адреса берутся только из серверных настроек. Посетитель не может изменить получателя. Подтверждение появляется после того, как почтовый сервер принял письмо. Это не гарантирует попадание во «Входящие», при проверке нужно также посмотреть «Спам». При ошибке данные остаются в форме, повторная отправка во время ожидания заблокирована.

Для Gmail заполните `SMTP_PASS` в `.env` паролем приложения, созданным в [настройках аккаунта Google](https://myaccount.google.com/apppasswords). Нужна двухэтапная проверка, подробности в [справке Google](https://support.google.com/accounts/answer/185833?hl=ru). Обычный пароль аккаунта не подходит. Укажите пароль приложения без пробелов. Не передавайте его в чат и не помещайте в `dist/`. `.env` исключён из Git. После изменения настроек перезапустите сервер.

Используются TLS и проверка сертификата Gmail. Размер запроса ограничен 16 КБ, частота отправки: 5 попыток за 10 минут с одного IP. Чужие браузерные источники отклоняются; это базовая защита, а не полноценная CAPTCHA. SMTP-ошибки и контакты не выводятся в журналы приложения. Сайт отдаёт только `dist/`, настройки и серверный код недоступны через браузер.

В браузере сохраняются только идентификаторы выбранных сервисов. Контактные данные формы не записываются в локальное хранилище или файлы сайта. Отправленные заявки хранятся в почте. При недоступном локальном хранилище набор работает до обновления страницы.

## Размещение

Для VDS загрузите проект в `/opt/it-global`, установите Node.js 22.21 или новее, выполните `npm ci --omit=dev` и заполните `.env`. На сервере задайте `NODE_ENV=production`, `PUBLIC_URL=https://its-global.ru`, `HOST=127.0.0.1` и `TRUST_PROXY=true` только при использовании локального Nginx из примера. Ограничьте доступ к `.env` владельцем процесса сайта (`chmod 600 .env`).

В `deploy/it-global.service` приведён пример запуска от отдельного пользователя `itglobal`; создайте этого пользователя и передайте ему каталог проекта. Проверьте путь к Node.js. В `deploy/nginx.conf` приведён HTTPS-прокси для `its-global.ru`; сначала выпустите сертификат для домена и проверьте пути к нему. После настройки включите службу и конфигурацию Nginx штатными средствами вашей ОС. Примеры не применяются автоматически и не заменяют настройки других сайтов.

Прокси должен заменять `X-Forwarded-For` реальным адресом клиента, а не дописывать его к входящему заголовку. Приложение доверяет этому заголовку только от прокси на том же сервере. При прямом запуске оставьте `TRUST_PROXY=false`. Не публикуйте порт 8765 отдельно от HTTPS-прокси.

После размещения откройте форму на `https://its-global.ru`, отправьте тестовую заявку и проверьте письмо в Gmail. Проверка реальной доставки требует настроенного пароля приложения; локальные тесты не отправляют письма на внешний адрес.

## Проверки

```sh
npm test
```

Полный доступный набор тестов выполняется последовательно в изолированном локальном контуре. Проверяются поля, тарифы и состав письма, HTTP-обработчик, ошибки, ограничения отправки, защищённость файлов и реальный обмен с локальным SMTP-стендом. Дополнительно проверяются готовый каталог, карта сайта, уникальные поисковые метаданные, локальные ссылки и файлы, перенаправления и кеширование, отключённая аналитика и состав её событий. Рабочие почтовые аккаунты и базы не используются. Аналитика проверяется в изолированной модели браузера без подключения к Яндексу.

## Страницы для поиска

- `/services/mailu/`: корпоративная почта на своём сервере.
- `/services/nextcloud/`: общие файлы, синхронизация и права доступа.
- `/services/onlyoffice/`: совместная работа с документами.
- `/services/espocrm/`: контакты, сделки и обращения клиентов.
- `/services/vaultwarden/`: рабочие пароли, коллекции и доступ сотрудников.
- `/services/openproject/`: задачи, сроки и диаграммы Ганта.
- `/services/jitsi/`: видеовстречи на своём домене и доступ участников.
- `/services/cloud-migration/`: перенос с облачных подписок в свою инфраструктуру.
- `/solutions/local-ai/`: внедрение локального ИИ.
- `/solutions/transcription/`: локальная транскрибация аудио и видео.
- `/solutions/speech-synthesis/`: синтез речи на своём сервере.
- `/solutions/document-assistant/`: ИИ-помощник по документам компании.

Чтобы добавить страницу, внесите описание в `content/services-pages.json` для сервиса или `content/solutions.json` для задачи ИИ и выполните:

```sh
npm run build:pages
```

Генератор обновляет страницы, готовые карточки каталога, ссылки на главной, `robots.txt`, `sitemap.xml` и `analytics-config.js`. После изменения продуктов в `dist/services.js` также запускайте генератор, чтобы исходный HTML и интерактивный каталог совпадали. В содержимом каждой страницы нужны собственные сценарии, требования и ответы, соответствующие её задаче. Заявка передаёт выбранную задачу в общую форму; остальной набор сервисов сохраняется. Страница переноса открывает консультацию без автоматического добавления лишнего продукта.

Основной адрес сайта: `https://its-global.ru`. Он задан в `content/site.json`. Генератор формирует абсолютные canonical, адреса Open Graph, BreadcrumbList и `dist/sitemap.xml` для этого домена. При смене домена обновите настройку и запустите генератор снова. Сервер отдаёт `index.html` внутри папок решений и добавляет завершающий `/` в адрес. Прямые адреса `/index.html` и вложенных `index.html` перенаправляются на соответствующий адрес папки с кодом 301; параметры запроса сохраняются.

Используются уникальные title и description, видимые хлебные крошки, связанные страницы и структурированные данные Service/Organization. Эти изменения подготавливают страницы к индексации, но не гарантируют позиции в поиске. Подключение Яндекс Вебмастера и Google Search Console выполняется после публикации и подтверждения домена.

Структура изучена на [Talkis](https://talkis.ru/) 13 октября 2026 года. Тексты написаны для услуг IT Global. Фактические ограничения сверены с документацией [Ollama](https://docs.ollama.com/faq), [Whisper](https://github.com/openai/whisper), [whisper.cpp](https://github.com/ggml-org/whisper.cpp), [Piper](https://github.com/OHF-Voice/piper1-gpl) и [Mailu](https://mailu.io/2024.06/). Условия использования проверяются для конкретной модели и голоса; типовой VDS из калькулятора подходит не для каждой ИИ-задачи.

## Загрузка изображений и кеширование

На страницах Mailu, Nextcloud, ONLYOFFICE и EspoCRM показаны реальные интерфейсы из официальных источников. Нажатие на превью открывает полный скриншот в новой вкладке. Источник и применимая лицензия указаны под изображением. Данные превью задаются в `content/services-pages.json`; страница перехода из облака повторно использует их через `previewServices`. Происхождение изображений описано в `dist/assets/business/README.md` и файлах `dist/assets/previews/*-source.md`. Скриншоты показывают демонстрационные интерфейсы, их состав зависит от версии и подключённых модулей.

Главный фон, иллюстрации преимуществ и безопасности, скриншоты Nextcloud и EspoCRM используются в WebP. Компактные скриншоты из документации Mailu и ONLYOFFICE сохранены в исходном PNG. Для главного фона и трёх иллюстраций предусмотрены уменьшенные варианты через `srcset`, чтобы телефоны не загружали избыточное изображение. Исходные PNG сохранены. Для повторной конвертации нужен Python с библиотекой Pillow и поддержкой WebP:

```sh
python scripts/optimize-images.py
```

Скрипт выводит размеры файлов и проверяет чтение созданных изображений. Скриншоты сервисов сохраняются без потерь. Десять основных WebP занимают около 0,91 МБ вместо 12,5 МБ исходных PNG, дополнительные варианты для узких экранов около 0,11 МБ.

HTML, карта сайта и `robots.txt` проверяются при каждом обращении. CSS и JavaScript также требуют проверки актуальности, чтобы после выкладки страницы не использовали устаревшую логику. Изображения и шрифты кешируются на сутки; при замене такого файла с немедленным показом используйте новое имя. Сервер отдаёт ETag и возвращает 304 для неизменившихся файлов. Ответы API не кешируются. Пример Nginx включает gzip для текстовых ресурсов; WebP повторно не сжимаются.

## Необязательная аналитика

Счётчик пока не создан. В `content/site.json` установлено `"metrikaId": null`, поэтому скрипт Яндекс Метрики не загружается и события не отправляются. Когда счётчик будет готов, замените `null` его положительным целым номером, выполните `npm run build:pages` и опубликуйте обновлённые файлы. Сам файл `dist/analytics-config.js` вручную не редактируйте.

В интерфейсе Метрики создайте три цели типа «JavaScript-событие» с точными идентификаторами:

- `phone_click`: нажатие на номер телефона.
- `request_open`: открытие формы заявки.
- `request_sent`: успешный ответ сервера после принятия письма почтовым сервером.

События не содержат имя, телефон или текст заявки. Адрес просмотра передаётся без параметров запроса и фрагмента, адрес источника перехода ограничен доменом. Вебвизор, карта кликов, автоматическое отслеживание ссылок и менеджер тегов отключены. Это подготовленное подключение, не действующий счётчик. Создание счётчика и настройка целей выполняются отдельно владельцем сайта.
